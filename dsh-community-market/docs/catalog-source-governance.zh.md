# 目录数据源治理与合作政策

[English](catalog-source-governance.md)

状态：适用于已经实现的 DSH Community Market 的现行治理政策。中英文版本具有同等效力。

本政策约束 Anywhere Labs 在 DSH Community Market 中作出的来源兼容、受审内置 adapter、合作标识和来源展示决定。Wire compatibility 仍以版本化的[目录提供方契约](catalog-provider-contract.zh.md)为准，runtime 安全边界仍以[安全策略](../SECURITY.zh.md)为准。

这是一项维护与治理承诺，不表示产品内已经实现 moderation 服务来自动执行政策。Market 没有中央目录后端，也不控制独立 provider 的目录内容或内部治理。

## 核心承诺

- 标准来源通过公开契约开放，不采用邀请制或中央 allowlist。
- 来源接入和技术审核使用公开、统一适用的标准。
- 商业关系、竞争关系、合法观点和受保护身份既不能购买优待，也不能成为排斥理由。
- 来源由用户自行选择；不设默认、优先、隐藏兜底或跨来源排名。
- 内置 adapter 或合作标识只披露关系或技术接入，不构成推荐。
- 限制措施必须有证据、符合比例、只作用于受影响边界，并允许复核。

## 各种来源状态分别表示什么

| 状态 | 表示什么 | 不表示什么 |
| --- | --- | --- |
| 标准来源 | 独立运营的数据源实现了公开 HTTPS JSON 契约。 | 不表示经过中央批准、建立合作、得到推荐或被产品打包。 |
| 用户添加的来源记录 | 用户在本地保存了一份标准来源 manifest，并可以明确选择它。 | 不表示该来源由 Anywhere Labs 收录或控制。 |
| 内置 adapter | Market 随包发布、经过评审和测试的本地代码，会把某个现有公开 API 转换为标准化契约。 | 不表示 provider、其目录治理或条目已经通过安全与质量审核。 |
| 合作来源 | 来源运营者与 Market 维护者存在已披露的接入合作关系。 | 不表示该来源是默认、优先、官方、推荐或兜底来源。 |
| 推荐或背书 | 依据另行发布的标准作出的独立、明确的信任判断。 | 当前任何来源状态、badge、目录收录或**可安装**卡片都不会产生这类判断。 |

`内置`和`合作`是两个独立事实。本地 adapter 说明 Market 如何读取 API；合作标识说明双方存在何种关系。两者都不会改变由用户确认来源选择的产品模型。当前 UI 只会根据经过审核的本地内置 provider definition 显示合作 badge；远程 manifest 不能自行声明合作身份。

## 通过契约开放接入

任何持续满足已发布版本化契约，以及统一适用的技术、安全、隐私、完整性与法律要求的数据源，用户均可自行添加和选择；无需事先批准、商业关系或修改 Market 代码。

标准路径不要求 provider 加入合作、使用 Anywhere Labs 服务、把目录提交中央审核，或把编辑权交给 Anywhere Labs。Host 对所有标准来源执行同一套 Schema、transport、provenance、网络和数据限制。符合契约的来源仍可能因临时网络错误或实现缺陷加载失败；这种运行故障不等于治理决定。

现有 API 无法直接实现标准数据结构时，provider 可以申请经过审核的内置 adapter。没有获得专用 adapter 不等于被排除在生态之外：provider 随时可以发布标准契约，直接走自助接入路径。

Market 的联邦化指独立所有权与共同互操作边界，不表示当前 v1 产品会聚合多个来源。各来源独立运营并遵循同一个公开边界，但每个浏览会话只请求和展示一个由用户选择的来源。Market 不会暗中跨来源合并、去重或排名。

## 中立与非歧视

Anywhere Labs 不会因为数据源运营者具有以下情况，而拒绝、降级、压制或附加技术接入条件：

- 付费、拒绝付费、提供赞助，或与 Anywhere Labs 没有商业关系；
- 与 Anywhere Labs、DSH Community Market 或合作 provider 构成竞争；
- 持有或表达合法观点或政治立场；
- 具有特定国籍、种族、族裔、宗教、性别、性别认同、性取向、残障，或适用法律保护的其他身份；
- 提出善意批评、执行互操作性测试、报告安全问题，或拒绝一项合作邀请。

这些因素同样不能放宽公开要求。任何代码、数据和行为都仍需遵守统一适用的技术、安全、隐私、完整性与法律标准。付款或赞助可以支持工程工作，但不能购买来源选择、优先级、兜底行为、推荐、较弱审核或更宽松的安全边界。

Package 级安装判断与来源接入彼此独立。受管安装器可以依据已发布的身份、integrity、runtime、lifecycle、兼容性和产品保护规则，让某个条目保持只读浏览或拒绝安装，而不会因此移除或惩罚报告该条目的来源。当前 package 规则见[安装与卸载](install-and-uninstall.zh.md)。

## 用户选择与数据最小化

- 新 profile 默认没有已选来源；只有本地用户的明确操作才能添加或选择来源。
- 用户可以保存、排序、切换和移除自己的来源记录。Provider 不能选择自己，也不能改变本地优先级。
- 除了用户添加标准来源时明确触发的 manifest 校验，只有已选来源会收到 provider page 与媒体请求。来源失败时，不得暗中切换到其他来源，也不得请求其他已保存来源。
- 在应用层，标准来源请求是匿名的：Market 不发送 ambient cookie、authorization header、client certificate 或 provider 提供的 header。Provider 仍会收到提供 HTTPS 服务所必需的普通网络信息，例如连接 IP 和 request metadata。
- Market 不会把 provider 的 analytics、评分、风险标签、官方标识或精选状态当成自己的结论；受审 adapter 即使保留这些字段，它们也仍是 provider claim。

来源运营者仍需自行负责隐私声明、日志、元数据权利、内容与法律义务。符合本政策或公开 Schema 不构成法律合规认证。

## 内置 adapter 审核

标准路径不需要合作审核。内置 adapter 不同，因为 Anywhere Labs 会发布并维护 provider-specific 代码。审核必须采用与来源立场无关的工程标准，包括：

- 稳定的公开 endpoint 文档和具有代表性的有界 response；
- 清晰的 attribution、provenance、元数据与媒体权利，以及可联系的责任人；
- 固定且受限的网络面，不允许远程代码、credential、command 或可配置 mapping 逻辑；
- 可确定地标准化到公开契约，包括来源内 identity 和分页行为；
- 已记录的 rate limit、与隐私有关的请求行为、失败语义和 provider 变更通知；
- 覆盖校验、限制、取消、origin 控制、完整扫描与安全失败的自动化测试；
- 对随 Market 发布的代码存在现实可行的维护责任人和维护成本。

工程资源会影响专用 adapter 何时能够开发或继续维护，但不能影响 provider 是否可以使用标准自助路径。Adapter 审核只覆盖 Market 拥有的集成代码，不是对全部目录条目、provider 组织或其未来行为的审核。

具体接入材料、评审和发布步骤见[目录接入与 adapter 指南](catalog-adapter-guide.zh.md)。

## 关系与利益冲突

当一个来源被标为合作来源，或在标准路径之外获得由项目控制的展示时，文档必须说明 provider、endpoint 或 API、adapter 类型、attribution 和接入关系的性质。

维护者必须披露理性用户或评审者会认为与决定相关的重大关系，包括赞助、付款或分成、所有权或控制、雇佣关系和共同治理。无需公开保密金额或合同原文，但不能利用保密条款制造具有误导性的独立或中立声明。

重大关系不得改变兼容或安全标准。存在直接利益冲突的维护者，在合理可行时不应独自作出影响该关联来源或其竞争方的最终决定；评审记录应说明冲突及其处理方式。

远程 manifest 中的 provider attribution 属于 provider 自述元数据，不能代替 Anywhere Labs 对关系的披露。

## 限制与比例原则

本项目不会集中下架用户拥有的标准来源。只有在证据表明存在以下情况时，项目才可以拒绝某个 response、拒绝某项操作，或暂停、移除由项目控制的内置接入：

- 不符合已发布的 Schema、transport、version 或 adapter contract；
- 存在具体的安全或隐私风险，包括试图绕过用户同意，或绕过受限网络与 renderer 边界；
- 来源身份或 provenance 存在重大虚假、冒充、数据损坏，或意图绕过校验的操纵行为；
- 严重或持续的资源滥用、不稳定，或违反已发布的运行限制；
- 拟议接入缺少必要权利或授权，包括项目需要随包发布的代码，或需要复制、展示、分发的元数据与媒体；
- 适用法律或有效法律程序提出了具体义务。

任何措施都必须依据已记录证据，并对同类情况采用同一规则。措施应当是能够处理风险的最小范围，例如拒绝格式错误的数据、让 package 保持只读浏览、禁用一项不安全操作，或暂停一个内置 adapter，而不是停用无关来源或功能。范围和持续时间应与风险相称；声明的问题修复或理由不再存在时，应解除或缩小限制。恢复已移除的内置 adapter 仍需经过普通评审与发布流程。

移除内置 adapter 不会禁止 provider 改为发布符合契约的标准来源，除非同一来源仍被统一适用的 runtime 安全或法律边界阻止。

## 紧急处置

出现可信的活跃安全威胁、即时平台完整性风险或要求立即采取行动的具体法律义务时，维护者可以在普通通知前临时停用由项目控制的 adapter 或受影响操作。维护者必须记录时间、证据范围、影响边界和理由；在安全且合法时通知运营者；尽快复核措施；并在紧急理由结束时解除或缩小限制。这里描述的是项目控制的代码、发布或本地产品边界，不表示项目拥有远程关闭用户自有来源的开关。

紧急措施不是对来源运营者、组织或社区作出的最终事实认定。

## 通知与复核

对于涉及内置 adapter 或合作状态的非紧急不利决定，项目应提供公开记录；公开会产生安全、隐私、合同或法律风险时，应改为适当的私下通知。记录或通知应说明：

- 受影响的 provider、manifest、adapter 或 operation；
- 所依据的公开标准与证据；
- 措施范围和生效时间；
- 具体整改方式或兼容路径；
- 如何申请复核。

普通治理、兼容或合作决定请在 [DSH Desktop 仓库](https://github.com/anywhere-labs/deepseek-harness-desktop)提交 issue 或 PR。请附上来源 identity、manifest 或 API endpoint、希望复核的决定和相关技术证据。未修复漏洞请按[安全策略](../SECURITY.zh.md)私下报告，不要提交公开 issue。

复核继续使用同一套公开标准。在合理可行时，应由未参与原决定的维护者参与。除非公开内容会产生安全、隐私、合同或法律风险，结果及理由应当公开。本流程不承诺固定响应时间，也不表示产品内已经提供申诉界面。

## 政策变更

修改本政策时，应通过公开 PR 同步更新中英文版本，并提供通俗易懂的说明。技术兼容性变化还必须遵循目录提供方契约的版本规则。安全敏感细节可以暂缓披露，但在能够安全、合法公开时，应发布政策变更及非敏感理由。
